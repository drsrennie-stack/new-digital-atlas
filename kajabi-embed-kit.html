The course site stays on GitHub Pages. Kajabi shows it through an iframe. One block puts the whole site in a single frame with navigation working inside it. Below that, every page is listed with a live preview and its own block, for when you want one tool on its own.

The short answer

One embed, the whole site inside it

You do not need twenty-eight embeds. Paste this one block on a single Kajabi page and the dock, the links and every tool work inside that one frame. The student never leaves the Kajabi page, and the frame resizes and scrolls to the top of each new page as they move.

The catch this solves. Every internal link on the course site carries target="_top", which is right for Canvas and exactly wrong here: one click and the whole Kajabi page navigates away to github.io. The ?embed=solo flag on the address switches the site into keeping navigation inside the frame, and carries itself forward on every link so it survives every hop.

    Reference
    
The height receiver, and why it is written this way

    
You do not need to install this separately. It is already inside every block you copy.
      It is here so the behavior is documented rather than mysterious.

    
Every page in the repo posts its height to the parent window as the content changes.
      The parent has to listen and resize the frame, or the sender is talking to nobody. The catch is that
      the repo grew two message shapes: older pages send {type:'resize', id:'...'} and
      newer ones send {type:'resize', frameId:'...'}. A receiver keyed on either name works
      for some pages and silently fails for the rest.

    
So this one ignores the name and matches the window the message came from
      against the frame's own contentWindow. A message can only have come from the frame that
      sent it, which makes this both stricter than an id check and immune to the naming split. It works
      with every page in the repo.
